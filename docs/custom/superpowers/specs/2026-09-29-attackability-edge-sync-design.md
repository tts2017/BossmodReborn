# 殴れる敵の有無の切替で時計を合わせ直す 設計

日付: 2026-09-29
関連: `docs/superpowers/plans/2026-09-26-unified-timeline-results.md`(Eald'narche 節の後)、memory `dt-alliance-hp-gated-disengage`

## 1. 背景

Al-Zahbi(zone 1368、A31)はウェーブ戦で、NoTarget 窓の端は「前のウェーブを倒し切った時刻」で決まる。火力で窓の開始が 78.6〜94.4 s とずれる。

- フォロワーは `CheckAgainstWorld` で「予測した殴れる/殴れない」と実際が 3 s(`ContradictionGrace`)食い違うと sequence を捨てる。アライアンス holdout 23 本で、pull 終了時以外のドロップは Al-Zahbi の 4 件(10 pull 中 4)。どれも窓の端のずれ(3〜9 s)が原因。
- 捨てた後は同期点が無い(sequence の同期点はモジュール対象の 0x4DA6 の技だけで、0x4DA6 は 36 s 前後で倒れる)ので、その pull では予告が戻らない。
- 既存の `OnTargetableChanged` は名前付きボスの対象可否の変化で合わせ直す(許容 20 s)。撃破による全滅は死亡なので対象外、名前付きボスも既に倒れている。
- 窓が実際に始まった後も、公開中の復帰時刻は予測時刻のまま(最大 9 s ずれる)。

## 2. 決定

### 2.1 殴れる敵の有無の切替を同期点にする

`AnyAttackable()`(戦闘中・非味方・生存・対象可能な敵が 1 体でもいるか)の値が変わった時刻を「端」とする。

- 殴れる → 殴れない: NoTarget 窓の開始に合わせる。
- 殴れない → 殴れる: NoTarget 窓の終了に合わせる。
- 候補は、追従中の sequence の NoTarget 窓のうち確信度が `MinWindowConfidence` 以上のもの。`BossOIDs` の有無によらず NoTarget 窓を使う(既存の `MatchTargetableEdge` はボス名付きなら BossUntargetable を使うが、ここでは「全滅」を見ているので NoTarget)。
- 端の時計時刻との差が `SyncTolerance`(6 s)以内の候補のうち最も近いものに合わせる。無ければ何もしない。
- 分岐が未決の sequence では、`NextDowntime` と同じ上限(`DecisionTime - BranchWindowEpsilon`)以降に始まる窓は候補にしない(開始・終了とも)。
- sequence が無い、時計が NaN、sequence が尽きている(`RefreshExhausted`)ときは何もしない。追跡する敵(`FindTrackedEnemy(false)`)がいないときも何もしない(戦闘外)。

### 2.2 切替は 1 s 続いてから採用する

雑魚の死亡の合間などで一瞬だけ殴れる敵がいなくなることがあるので、切替後の値が `EdgeSettle = 1 s` 続いたときに採用する。採用時は、時計を「切替が起きた実時刻」に遡って合わせる(`_anchorAt = 切替の実時刻`、`_anchorTime = 窓の端`)。合わせたら `Confirm()` し、同期時刻を更新する(既存の `Anchor` と同じ扱い。`_syncedAt` は切替の実時刻ではなく採用時の現在時刻でよい)。

1 s 未満で元に戻った切替は捨てる。

### 2.3 端の遅れは食い違いとして数えない

- 窓の中と予測しているのに殴れる敵がいる(窓の開始が遅れている)とき、`TimelineTime - w.Start <= SyncTolerance` の間は食い違いとして数えない。実際に消えたら 2.1 で開始に合わせる。
- 窓の後と予測しているのに殴れる敵がいない(窓の終了が遅れている)とき、直前に終わった窓 w について `TimelineTime - w.End <= SyncTolerance` の間は食い違いとして数えない。実際に現れたら 2.1 で終了に合わせる。
- 許容を過ぎたら、従来どおり 3 s の猶予の後に sequence を捨てる。
- 端が早く来た場合(開始・終了とも)は 2.1 の切替で合わせ直されるので、食い違いは起きない。6 s より早い場合は従来どおり。

### 2.4 開始の遅れを待つ間は、その窓を公開しない

2.3 の前半(窓の中と予測、実際は殴れる、許容内)の間、`NextDowntime` はその窓を返さない(「今離脱」と出し続けると、実際には敵が残っているのに温存させてしまう)。そのまま後ろの窓も返さない(何も公開しない)。実際に消えたら 2.1 で開始に合わせ、以後は正しい復帰時刻を公開する。

終了の遅れを待つ間は特別な扱いをしない(殴れる敵がいないので、公開内容はローテーションの選択に影響しにくい)。

## 3. 計測

`tools/timeline_hint_harness` に「窓に入った後の復帰時刻の精度」を足す。

- 各真値窓(8.5 s 以上)について、窓開始 +1 s 以降・窓終了前の公開のうち、公開中の離脱が現在(`LossAt <= At + 0.5 s`)のものの最初の 1 つを取り、`ReturnAt - 真値の終了` を誤差とする。
- 集計行の末尾に `inwin=<件数> inwin_return_err_median=<中央値> inwin_return_err_p90=<p90>`(絶対値)を足す。既存のキーと CSV は変えない。

採否: アライアンス holdout・自データ内、旧 47 本の 3 条件、FFLogs、自リプレイの 7 条件で、hit を減らさず false alarm を増やさないこと。加えて inwin の件数と誤差が悪化しないこと。Al-Zahbi の 4 件のドロップが消えることをトレースで確かめる。

## 4. 対象外

窓開始直前の HP による離脱時刻の補正(試算で最後の約 5 s しか効かず、見送り)。W2 以降の技を同期点に加えること(撃破時間のばらつきが残り、効果が小さい)。
